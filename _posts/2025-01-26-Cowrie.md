In this post I am configuring Cowrie Honeypot, and testing it with a Hydra bruteforce attack

# Installation

First, it is mandatory updating the system packages through the following command

- `sudo apt-get update`

In order to be able to execute Cowrie without any dependency issues, a virtual environment such as conda,  pyenv, venv, or virtualenv; it is a must. In this case I am using `virtualenv`. To create a virtualenv named `cowrieEnv` execute the following command

- `virtualenv cowrieEnv`

Access the virtual environment just created through the following command from the directory it has been created

- `source cowrieEnv/bin/activate`

![](/img/cowrieHoneypot/IMG 1.png)

To continue, download the cowrie honeypot from the [github repository](https://github.com/cowrie/cowrie.git)

![](/img/cowrieHoneypot/IMG 2.png)

Once downloaded, install the dependencies. No dependency issues are expected since these are being installed in the virtual environment that has been created previously. To do so, execute the following command

- `pip install -r requirements.txt`


![](/img/cowrieHoneypot/IMG 3.png)

# Configuration

In the following step, I am copying the file `cowrie.cfg.dist` into a new file named `cowrie.cfg`. This step is important as `cowrie.cfg.dist` is the default configuration file, and it will remain intact in case we need to take it back, used "like a template. `cowrie.cfg` file is intended to be used as a customisable configuration file. The .dist file can be overwritten by upgrades, cowrie.cfg will not be touched.

- `cp etc/cowrie.cfg.dist etc/cowrie.cfg`

![](/img/cowrieHoneypot/IMG 4.png)


By inspecting the file, it can be seen the honeypot it is configured to ran on port 2222. This is not the default SSH port, but I leave it this way in this case

![](/img/cowrieHoneypot/IMG 8.png)

# Execution

To start cowrie, just run the binary found in the `/bin` directory

- `./bin/cowrie start`

By running the command `status`, cowrie will print the process ID. Additionally, we can inspect the port `2222` has been opened throught the `netstat` tool. Please see the image below, where I find the `TCP` (-t) port listening (-l) on port (-p) 2222, which matches by the process ID

![](/img/cowrieHoneypot/IMG 9.png)

Logs are stored in the directory `log`. In the following example, i perform 3 ssh login attempts on port 2222, where the honeypot is held

![](/img/cowrieHoneypot/IMG 10.png)

Logs are not only stored as a log file, but also in a json computable format. In order to view the logs easily, I have used the online tool [jsonviewer](https://liruqi.github.io/jsonviewer/)

![](/img/cowrieHoneypot/IMG 11.png)
